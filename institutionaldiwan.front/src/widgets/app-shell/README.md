# `src/widgets/app-shell` — RTL Application Shell, Sidebar & Header Widget
> **Status:** Implemented (Phase 1, 2026-10-27) — wraps every shell route (the standalone `/change-password` page is outside it): permission-filtered sidebar, sticky header, mobile drawer, shell/user/item context menus, and the display-settings dialog (theme + independent Legacy/Modern appearance + density + page motion + tutorial mode).
## 1. Purpose
Composes the authenticated Arabic RTL workspace chrome around `<Outlet />`: a collapsible navigation sidebar filtered by the session's effective permissions, a sticky top bar with shell actions, theme toggle, and account menu, a mobile overlay drawer, and the global right-click surface.

The shell owns the desktop-style chrome: a context menu on page content (refresh queries, toggle density, toggle page motion, open display settings) and context menus on sidebar entries (open, copy link, collapse/expand group). All shell actions are also keyboard reachable through the shared context-menu primitive.

Each page inside the shell fades up once when its route path changes (the page container is keyed by
`location.pathname` and carries `animate-page-in`). The user can stop that motion — and the overlay
entrances and colour transitions with it — from the display-settings dialog or the shell menu; see
`model/motion.ts` and the `html[data-motion]` rules in `src/app/styles/README.md`.
## 2. Strict FSD Rules
- Allowed Imports: `src/features/auth`, `src/entities/user`, `src/entities/branding`, `src/entities/numbering-registry`, and `src/shared/*`.
- Forbidden Imports: NEVER import from `src/app`, `src/pages`, or sibling `src/widgets/*` slices.
- Public API: exports `AppShell`, `AppSidebar`, and `AppHeader` via `src/widgets/app-shell/index.ts`; `AppRouter` mounts only `<AppShell />`.
- Logout is not reimplemented here: the account menu calls `useLogout` from `features/auth`, which owns token/session/query-cache teardown.
## 3. Contents & Segments
- `ui/AppShell.tsx` — Layout wrapper: desktop sticky sidebar, mobile overlay drawer (Escape + body scroll lock), `AppHeader`, the page `<main>` wrapped in a shell `ContextMenu` (keyboard `Shift+F10` / `ContextMenu` dispatch), `SettingsDialog`, the density effect that applies `html[data-density]` and persists `diwan.density` (attribute removed on unmount so `/login` keeps default density), and the motion effect that applies `html[data-motion]`; `diwan.motion` is written only when the user actually chooses, so the system `prefers-reduced-motion` request keeps steering until then. Its page container is keyed by `location.pathname` and carries `animate-page-in`, so every route change replays the entrance. The shell menu also carries «إيقاف/تفعيل الوضع التعليمي», reading `useTutorial()` and calling `setTutorialChoice` — no state of its own, because the guide primitives subscribe to the same store. For the `superadmin` account only (`user.username === 'superadmin'`, absent from the DOM for everyone else) it adds «إيقاف/تفعيل تعديل التسميات» over `useLabelEdit()`/`setLabelEditMode`, and while edit mode is on a sticky top banner («وضع تعديل التسميات مفعّل — انقر أي نص لتعديله…») with an «إنهاء الوضع» button reminds the admin it is active (UI labels plan, Phase 2).
- `ui/AppSidebar.tsx` — Brand block (the uploaded logo and stored institution name through `entities/branding`), collapse toggle, permission-filtered nav groups (`filterNavGroups`), active `NavLink` styling, disabled entries with the Arabic «قريبًا» badge for slices that have not landed, per-item `ContextMenu` (فتح / نسخ الرابط / طي المجموعة) with clipboard success/error toasts, and `Shift+F10` support on links. All navigation text (group/item labels, tagline, menu entries, aria-labels/titles, the «قريبًا» badge, copy toasts) resolves from the UI-labels store: visible text via `<Label k>`, string props via a `resolveLabel(key, overrides)` helper subscribed to `useLabelsStore`, so a rename repaints expanded and collapsed modes alike (UI labels plan, Phase 1). Each entry renders as one inline row (18px icon + label, `flex items-center gap-3`); the `NavLink` itself keeps a static `className` and hands its active state to an inner `<span>` render prop, because the context-menu trigger clones the link through Radix `Slot`, which stringifies a function `className` and silently drops all styling. Under the «الوثائق» entry (expanded sidebar only) it mounts `DocumentsRegisterNav`. A group marked `standalone` renders with no collapsible header: its items sit under a semibold row closed by a hairline, `labelKey` becomes the list's `aria-label` only, and the per-item context menu drops the «طي المجموعة» entry.
- `ui/DocumentsRegisterNav.tsx` — The caller's primary-department active registers (`useDepartmentRegistries`, gated on `NUMBERING_VIEW`) as indented selection buttons under «الوثائق». Clicking one only writes the `diwan.documents.selectedRegistry.v1` preference (`writeSelectedRegistryId`) that preselects the register in the create-document form — it never navigates. The selected row (stored choice if still valid, else the first register) is highlighted with `aria-pressed`; nothing renders while loading, without the permission, or with no active register.
- `ui/AppHeader.tsx` — Mobile menu trigger, current-route title, shell-actions `DropdownMenu`, `ThemeToggle`, and the account `DropdownMenu` (avatar initial, username, roles; تغيير كلمة المرور، إعدادات العرض، then danger تسجيل الخروج).
- `ui/SettingsDialog.tsx` — Display settings dialog: independent theme choice (فاتح / داكن / حسب النظام) and site-wide appearance choice (الكلاسيكي / الحديث, from `useAppearanceChoice`), density choice (مريح / مضغوط), motion choice (حركات التنقل: مفعّلة / متوقفة), and tutorial choice (الوضع التعليمي: مفعّل / متوقف) — each fieldset uses `aria-pressed` state plus an Arabic note about what the setting does. Theme and tutorial read their stores directly (`useThemeChoice`, `useTutorial`) because the surfaces that consume them subscribe too, so the shell holds no state to thread for those two.
- `model/shell-nav.ts` — `SHELL_NAV_GROUPS` (نظرة عامة، الملفات، المراسلات، التنظيم، إدارة الوصول، الرقابة والتدقيق), permission codes, and `available` flags. «الملفات» is its own group (`standalone: true`) directly after the overview: Drive is a module with its own permission and workspace, so it no longer sits as the last item of «المراسلات»; a `standalone` group carries `labelKey` for its accessible name but renders no header. Each group and item carries a `labelKey` (UI labels catalog, `@/shared/config`) instead of a fixed `label`; the renderer resolves it through the labels store so an administrator's rename applies live. Dashboard, documents, movements, numbering, departments, institution settings, users, roles, employees, and audit are available; remaining entries show «قريبًا». Both organization entries require `DEPARTMENT_MANAGE`. `filterNavGroups` hides unpermitted items/empty groups; `findNavItem` drives route titles.
- `model/density.ts` — `Density`, `getStoredDensity`, `applyDensity` (`html[data-density]`), `persistDensity` (`diwan.density`).
- `model/motion.ts` — `Motion` (`on` / `off`), `getStoredMotion`, `applyMotion` (`html[data-motion]`), `persistMotion` (`diwan.motion`). With no stored choice it follows the system `prefers-reduced-motion` request, and the `index.html` boot script resolves the same way before first paint so the first page entrance already honours it.
- `index.ts` — Public API barrel file.
- `ui/SettingsDialog.tsx` keeps the Legacy/Modern appearance selector separate from Light/Dark/System; `shared/lib/appearance` owns the persisted preference, and `index.html` applies it before first paint.
