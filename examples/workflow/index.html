كيف تمرّ الوثيقة داخل نظام الديوان؟

هذه الصفحة مستقلة (HTML + CSS + JavaScript فقط، بلا مكتبات ولا اتصال بالخادم). تشرح الفكرة العامة للنظام ثم تتيح لك تشغيل دورة حياة وثيقة كاملة بنفسك: تبدّل الدور، تنفّذ الإجراءات، وترى ما يحدث للحالة والرقم الرسمي وموقع الوثيقة والإشعارات وسلسلة التدقيق. المحاكاة مبسّطة، لكن قواعدها مأخوذة من institutionaldiwan.front/knowledge.md.

١ — الصورة العامة

نظام مراسلات مؤسساتي يسجّل الوثائق، يمنحها أرقاماً رسمية، يوجّهها بين الأقسام، ويحتفظ بأثر تدقيق لا يمكن العبث به.

🖥️ الواجهة React 19

  • عربية أولاً (RTL) بمظهرين فاتح وداكن
  • تعرض الصلاحيات كأزرار مفعّلة أو مخفية
  • تعرض رسائل الخطأ بالعربية فقط

🔌 الواجهة البرمجية ASP.NET Core 10

  • مسارات /api/... ومحور /hubs/notifications
  • تتحقق من الصلاحية ثم من نطاق القسم ثم من مستوى الوصول للوثيقة
  • أخطاء بصيغة RFC 7807

⚙️ التطبيق والنطاق CQRS

  • أوامر واستعلامات ومدقّقات
  • قواعد العمل (الحالات، الحركات، الترقيم)
  • أحداث نطاق تغذّي الإشعارات والتدقيق

🗄️ البنية التحتية SQL Server

  • EF Core والترحيلات
  • تخزين الملفات مع SHA-256 لكل نسخة
  • صندوق صادر (Outbox) ومهام خلفية

اتجاه الاعتماد في الكود: Domain ← Application ← Infrastructure ← Server؛ والواجهة مشروع مستقل يتكلم مع الخادم عبر /api فقط.

٢ — دورة حياة الوثيقة (محاكاة تفاعلية)

ابدأ بـ«إنشاء مسودة»، أو اضغط «تشغيل السيناريو الكامل». جرّب أيضاً: الاستلام قبل تسجيل الوثيقة في سجل القسم (سيُرفض)، أو إضافة مرفق بعد الأرشفة، أو الدخول بدور «مطّلع» لترى كيف تُعطَّل الأزرار.

            شكل الخطأ عند الرفض

            كل خطأ في الخادم يعود بصيغة ProblemDetails، وعنوانه (title) هو رمز الخطأ. الواجهة لا تعرض النص الإنجليزي أبداً بل تترجم الرمز إلى العربية. آخر خطأ في المحاكاة يظهر هنا (رمز «الاستلام قبل التسجيل» توضيحي، أما Correspondence.DocumentArchived فحقيقي):

            // لم يحدث خطأ بعد — جرّب إضافة مرفق بعد الأرشفة.

            ٣ — وحدات النظام (Modules)

            كل وحدة مسؤولة عن جزء من الدورة. مرّر المؤشر على البطاقة لترى أين تظهر في المحاكاة أعلاه.

            ٤ — القواعد التي تحكم كل خطوة

            ثلاث بوابات قبل أي إجراء

            1. الصلاحية: رمز مثل DOCUMENT_EDIT داخل الرمز المميّز (JWT). عددها ١٧ صلاحية ومصدرها الوحيد Permissions.cs.
            2. النطاق: المستخدم ذو نطاق «قسم» لا يتصرف إلا بالوثائق والحركات التي تمسّ قسمه؛ نطاق «النظام» يرى الجميع.
            3. مستوى الوصول للوثيقة: VIEW للقراءة، DOWNLOAD للتعديل والتنزيل، MANAGE للإلغاء ورفع المرفقات — ويُمنح بالإنشاء أو بمنح صريح.

            مصفوفة الأدوار في المحاكاة

            قواعد تستحق الانتباه

            • لا يمكن الاستلام في الحركة قبل تسجيل الوثيقة في سجل القسم المستلم (تسجيل القسم يتطلب NUMBERING_MANAGE).
            • الرقم الرسمي فريد لكل سنة؛ تكراره يُرجع Numbering.OfficialNumberTaken (409).
            • الوثيقة المؤرشفة مجمّدة: ترفض المشاركين والمرفقات والأرقام (Correspondence.DocumentArchived) حتى فك الأرشفة، بينما تبقى القراءة والتنزيل والتحقق من التجزئة.
            • الفاعل لا يُشعَر أبداً بإجرائه، والوثيقة السرية تُعلَن لمنشئها وأصحاب المنح فقط.
            • كل طلب مصادَق يُسجَّل في التدقيق — حتى القراءة والفشل — ويُربط بحلقة تجزئة؛ تعديل أي سطر قديم يكسر السلسلة ويكشفه فحص السلامة.
            • فحص السلامة يرجع بـ200 حتى حين isValid: false — اقرأ المحتوى لا رمز الحالة.
            مثال توضيحي مستقل — لا يتصل بالخادم ولا يحفظ بيانات. الأسماء والأرقام وسلسلة التجزئة (FNV مبسّطة) وهمية للشرح؛ المرجع الفعلي للمسارات والصلاحيات هو knowledge.md.
