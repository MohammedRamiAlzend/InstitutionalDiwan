## 1. الهدف

تمكين الإدارة من تعريف حقول إضافية لكل نوع وثيقة (`DocumentType`) ديناميكيًا دون تعديل الكود أو قاعدة البيانات، مع إصدارات (Versions) للمخطط، بحيث لا يتأثر أي وثيقة بتعديلات الإدارة اللاحقة. حقول `Document` الحالية (العنوان، الملخص، السرية، الأولوية…) تبقى ثابتة لأن الترقيم والحركات والتدقيق تعتمد عليها.

## 2. القرارات المعتمدة

| # | القرار |
| --- | --- |
| 1 | الحقول **لكل نوع وثيقة** (لا حقول عامة مشتركة). |
| 2 | **الفلترة والبحث** في السجل بالحقول الديناميكية مطلوبة ← تخزين هجين بأعمدة مكتوبة حسب النوع. |
| 3 | أنواع البيانات: نص، نص طويل، رقم، تاريخ، نعم/لا، قائمة اختيار. النص يدعم **Regex** مع رسالة خطأ عربية يحددها المدير. |
| 4 | **إصدارات المخطط:** النسخة المنشورة غير قابلة للتعديل؛ أي تغيير = نسخة جديدة. |
| 5 | **الوثيقة تتثبّت على النسخة التي أُنشئت عليها** عند `CreateDraft` ولا تتغير أبدًا (لا ترقية تلقائية ولا يدوية). |
| 6 | القيم قابلة للتعديل في المسودة فقط، وتُقفل عند التسجيل الرسمي (`Register`). |
| 7 | إدارة الحقول والنسخ بصلاحية `LOOKUP_MANAGE` الحالية. |

## 3. النموذج

| الكيان | الغرض |
| --- | --- |
| `DocumentField` | هوية الحقل الثابتة: `Id`, `DocumentTypeId`, `Key` (غير قابل للتغيير بعد الإنشاء)، `DataType` (غير قابل للتغيير). القيم مربوطة به. |
| `DocumentTypeSchemaVersion` | نسخة مخطط لنوع وثيقة: `Id`, `DocumentTypeId`, `VersionNumber`, `Status` (`Draft`/`Published`/`Retired`), `PublishedAt`, `PublishedByUserId`. |
| `DocumentTypeSchemaVersionField` | إعدادات الحقل داخل نسخة: `LabelAr`, `IsRequired`, `DisplayOrder`, `RegexPattern`, `RegexErrorMessageAr`, `MinValue`/`MaxValue`/`MaxLength`, `Options` (لقائمة الاختيار). |
| `DocumentFieldValue` | قيمة حقل لوثيقة: `DocumentId`, `DocumentFieldId`, و`TextValue` / `NumberValue` / `DateValue` / `BoolValue` / `OptionKey` (واحد فقط معبّأ حسب النوع). |
| `Document.SchemaVersionId` | عمود جديد nullable، يُحدَّد عند `CreateDraft` ولا يتغير. |

## 4. القواعد

1. **النشر:** تعديل المخطط يتم على نسخة `Draft` واحدة فقط لكل نوع وثيقة؛ `Publish` يجمّدها ويحوّل النسخة المنشورة السابقة إلى `Retired` (تبقى مقروءة للوثائق المثبّتة عليها).
2. **إنشاء مسودة:** `CreateDraft` يثبّت `SchemaVersionId` على آخر نسخة `Published` للنوع. إن لم توجد نسخة منشورة ← `SchemaVersionId = null` وتُنشأ الوثيقة بلا حقول ديناميكية.
3. **لا ترقية:** لا يوجد أي أمر يغيّر `SchemaVersionId` بعد الإنشاء.
4. **التحقق:** القيم تُتحقق مقابل **نسخة الوثيقة المثبّتة** (النوع، الإجباري، Regex، الحدود، مفتاح الخيار). الحقول المجهولة للنسخة تُرفض.
5. **Regex:** يُقيَّم بـ `Regex` مع **مهلة تنفيذ** (مثلًا 250ms) ويُتحقق من صحة النمط وقت الحفظ؛ نمط غير صالح أو انتهاء المهلة = خطأ دومين.
6. **التسجيل:** `Register` يتحقق من اكتمال الحقول الإجبارية في نسخة الوثيقة ثم يقفل القيم.
7. **حذف حقل:** غير مسموح؛ يُزال من النسخة التالية فقط (القيم القديمة تبقى). تغيير `DataType` أو `Key` ممنوع.
8. **حدود:** أقصى عدد حقول لكل نسخة (اقتراح: 50) وأقصى طول Regex (اقتراح: 500).
9. **التدقيق (Module 09):** نشر نسخة، إنشاء حقل، تعديل قيمة في مسودة — كلها تُسجَّل بالـ audit log.

## 5. المراحل

### المرحلة 0 — Domain
- كيانات `DocumentField`, `DocumentTypeSchemaVersion` (+ سلوك `Publish`), `DocumentTypeSchemaVersionField`, `DocumentFieldValue` تحت `Entities/Correspondence/`.
- أخطاء دومين جديدة (`DocumentFields.*`) في `Errors/`.
- تعديل `Document.CreateDraft` ليستقبل `schemaVersionId` وإضافة `Register` check للحقول الإجبارية (عبر خدمة تحقق تُمرَّر القيم).
- عقود المستودعات في `Repositories/`.

### المرحلة 1 — Infrastructure
- `Configurations/` للكيانات الجديدة: فهرس فريد `(DocumentTypeId, Key)`، فهرس فريد `(DocumentTypeId, VersionNumber)`، **نسخة `Draft` واحدة فقط لكل نوع** (filtered unique index)، وفهارس على أعمدة `DocumentFieldValue` للفلترة.
- Migration جديد؛ تحديث seed إن لزم؛ تنفيذ المستودعات.

### المرحلة 2 — Application
- أوامر: إنشاء حقل، تعديل إعدادات حقل في نسخة مسودة، إنشاء/تجاهل نسخة مسودة، نشر نسخة.
- استعلامات: قائمة النسخ، تفاصيل نسخة، **مخطط نوع الوثيقة الحالي** (للواجهة عند إنشاء وثيقة)، **مخطط وثيقة معيّنة** (نسختها المثبّتة).
- Validators، وتعديل `CreateDraft` / `UpdateDraftMetadata` ليقبلا `fieldValues: [{fieldKey, value}]`.
- فلترة السجل بـ `fieldFilters` (يتطلب قرارًا لشكل الـ query، انظر §7).

### المرحلة 3 — Server
- `DocumentFieldsController` (إدارة المخطط والنسخ) وتعديل `DocumentsController`.
- عقود HTTP في `Contracts/`، وملخص ووصف ومثال لكل مسار ومعامل (`OpenApiDocumentationTests` يفشل البناء بدونها).
- ربط أخطاء الدومين بـ ProblemDetails.

### المرحلة 4 — Tests
- Domain: النشر، التثبيت، قواعد التحقق، Regex ومهلته، حدود الأنواع.
- Application: validators والأوامر والاستعلامات.
- Persistence: الفهارس الفريدة والـ filtered index.
- Server: تكامل المسارات وOpenAPI والصلاحيات.
- حالات حرجة: نشر نسخة جديدة والمسودة القديمة تحافظ على نسختها؛ حقل إجباري في نسخة جديدة لا يكسر وثائق نسخة قديمة؛ محاولة تغيير `DataType`؛ Regex خبيث.
