# خطة الوحدة 01 — إدارة جداول المراجع (Lookups) في الواجهة الأمامية

> **الحالة: منفّذة (2026-11-04) — `npm run build` و`npm run lint` ناجحان، وجُرّبت الإضافة والمعرّف المكرر وكتالوج للقراءة فقط وصلاحية 403 على API حي؛ لم تُفحص بصريًا حالة المستخدم بلا `LOOKUP_MANAGE` والوضع الداكن والجوال. المرحلة ب الاختيارية مؤجلة. تبيّن أن الكتالوجات 33 فعلًا.**

## 1. الهدف

تمكين مستخدم يملك `LOOKUP_MANAGE` من إدارة الجداول المرجعية (أنواع الوثائق، الأولويات، مواقع الأرشفة…) من الواجهة دون استدعاء API يدويًا:

- صفحة **`/lookups`** تعرض كتالوجًا مجمّعًا حسب الوحدة، وجدولًا بقيم الكتالوج المختار.
- **إضافة** قيمة (معرّف ثابت يختاره المدير + تسمية إنجليزية + تسمية عربية).
- **تعديل التسميتين** (المعرّف لا يتغير).
- **إيقاف / إعادة تفعيل** قيمة، مع رسالة واضحة إذا كانت مستخدمة (`409`).
- انعكاس أي تغيير فورًا على القوائم المنسدلة في بقية الشاشات.

## 2. الحالة الراهنة

| العنصر | الحالة |
| --- | --- |
| API القراءة | ✅ `GET /api/lookups` (مفاتيح الكتالوجات)، `GET /api/lookups/{lookup}?includeInactive=`، `GET /{lookup}/{id}` |
| API الكتابة | ✅ `POST /{lookup}`، `PUT /{lookup}/{id}`، `PATCH /{lookup}/{id}/deactivate`، `PATCH /{lookup}/{id}/activate` — كلها بصلاحية `LOOKUP_MANAGE` |
| حقول القيمة | `id`, `desc`, `descAr`, `isActive`, `createdAt` — التسمية حتى 150 حرفًا ومطلوبة بلغتين، والمعرّف عدد صحيح موجب |
| الكتالوجات | 33 مفتاحًا في `LookupCatalog.Definitions` (يذكر `knowledge.md` رقم 34 — يُتحقَّق منه من `GET /api/lookups` ويُصحَّح الوثيقة) |
| كتالوجات للقراءة والتعديل فقط | `file-storage-providers` و`notification-types`: الإضافة ترجع `400 Lookup.CatalogReadOnly` (كيانات تحتاج حقولًا إضافية)، أما التعديل والتفعيل/الإيقاف فمتاحان |
| الإيقاف | يُرفض بـ `409 Lookup.EntryInUse` إذا أشار إلى القيمة أي مفتاح أجنبي (يُكتشف من بيانات EF الوصفية) |
| رسائل الخطأ العربية | ✅ موجودة لـ `Lookup.*` الثمانية في `errorMessages.ts` |
| طبقة القراءة في الواجهة | ✅ `entities/lookup`: `lookupApi.entries`، `lookupKeys`، `useLookupEntries` (`staleTime: Infinity`)، `LookupLabel`، و`LOOKUP_SLUGS` (27 مفتاحًا فقط) |
| الكتابة / الصفحة / المسار / عنصر القائمة | ❌ غير موجودة (عنصر «مخططات الحقول» يستعمل `LookupManage` لكنه شاشة مختلفة) |
| دليل تعليمي | ❌ |

## 3. الفجوات المطلوب سدّها

1. استدعاء قائمة الكتالوجات (`GET /api/lookups`) وعمليات الكتابة الأربع في `entities/lookup` و`features/lookup-manage`.
2. بيانات وصفية للعرض: اسم عربي لكل كتالوج + الوحدة التي ينتمي إليها + هل يقبل الإضافة.
3. اختيار الكتالوج (مجمّع) وجدول القيم بعقد الجداول الكامل.
4. حوار إضافة/تعديل بتحقق Zod يطابق التحقق الخلفي.
5. إبطال الذاكرة المؤقتة بعد الكتابة، لأن `useLookupEntries` لا ينتهي صلاحيته أبدًا.
6. مسار وعنصر قائمة وأدلة تعليمية ووثائق.

## 4. القرارات المعمارية (FSD الصارم)

| الطبقة | الشريحة | المحتوى |
| --- | --- | --- |
| `shared/config` | `lookupCatalogs.ts` | جدول ثابت `LOOKUP_CATALOG_META`: `slug → { labelAr, module, canCreate }`، و`LOOKUP_MODULE_GROUPS` للترتيب. الكتالوج غير المعروف يظهر باسمه الإنجليزي ضمن مجموعة «أخرى» حتى لا تُخفى كتالوجات جديدة |
| `shared/config` | `routes.ts` | `ROUTES.LOOKUPS = '/lookups'` |
| `shared/config` | `guides/lookups.ts` | أدلة تعليمية للصفحة |
| `entities/lookup` | امتداد | `lookupApi.catalogs()`، `lookupKeys.catalogs()`، `useLookupCatalogs()`؛ تصدير النوع `LookupEntryResponse` موجود مسبقًا. لا تغيير في سلوك `useLookupEntries` |
| `features/lookup-manage` | جديد | `lookupMutations.ts` (إنشاء، تعديل، إيقاف، تفعيل) + `schemas.ts` (Zod) + `LookupEntryFormDialog` + `index.ts`. كل نجاح يُبطل `lookupKeys.all` (يشمل كل التركيبات بما فيها `includeInactive`) |
| `widgets/lookup-admin` | جديد | `LookupCatalogPicker` (قائمة مجمّعة قابلة للبحث) و`LookupEntriesTable` (`DataTable`، `tableId="lookup-entries"`) |
| `pages/lookups` | جديد | `LookupsPage` بحدود 120 سطرًا: `GuideProvider pageId="lookups"` + `PageHeader` + الودجتان؛ الكتالوج المختار في `?catalog=` |
| `app` | `router` | مسار `/lookups` محروس بـ `LOOKUP_MANAGE` على نمط `document-schemas` |
| `widgets/app-shell` | `shell-nav.ts` | عنصر «الجداول المرجعية» في مجموعة «الرقابة والتدقيق»، أيقونة `Library`، صلاحية `LookupManage` |

قرارات تفصيلية:

- **عميل فقط (client-mode):** كل كتالوج محدود (عشرات الصفوف)، فيعيد الخادم مصفوفة عادية؛ البحث والفرز والترقيم داخل `DataTable` مع حفظ `search/sort/page` في الرابط عبر `useTableState`. نطلب دائمًا `includeInactive=true` في هذه الشاشة.
- **عدم الاعتماد على التحديث التفاؤلي:** الإضافة تتطلب المعرّف من المدير وقد ترجع `409`، فنكتفي بإبطال الاستعلام بعد النجاح.
- **المعرّف:** يُقترح في الحوار `max(id)+1` للكتالوج الحالي (قابل للتعديل)، ويُقفل عند التعديل. المعرّفات المرتبطة بثوابت في الواجهة (مثل `DOCUMENT_STATUS`) تُعرض بشارة «نظامية» انطلاقًا من `LOOKUP_FALLBACKS` ويُحذَّر قبل إيقافها.
- **الإيقاف:** يتطلب حوار تأكيد؛ عند `Lookup.EntryInUse` تُعرض الرسالة العربية الموجودة. التفعيل بلا تأكيد.
- **الكتالوجات للقراءة والتعديل فقط:** زر «إضافة» معطّل مع تلميح، ويُضمن ذلك من `canCreate` في البيانات الوصفية، مع بقاء معالجة `Lookup.CatalogReadOnly` احتياطًا.
- **الصلاحية:** الصفحة ومساراتها لـ `LOOKUP_MANAGE`؛ القراءة العامة عبر `useLookupEntries` لا تتغير. (ملاحظة: يُذكر في `knowledge.md` أن القراءة تتطلب `DOCUMENT_VIEW` بينما الـ controller لا يضع سياسة على `GET` — يُتحقَّق ويُصحَّح الأقل دقة.)
- **القوائم المنسدلة الحية:** بعد الإبطال تُعاد قراءة الكتالوجات النشطة تلقائيًا؛ لا حاجة لتغيير `LOOKUP_FALLBACKS`.

## 5. المراحل

### المرحلة 0 — الأساس
- `ROUTES.LOOKUPS`، ملف `lookupCatalogs.ts` (33 كتالوجًا بأسماء عربية وتجميع حسب الوحدات 01–10)، تصدير في barrel الإعدادات.
- اختبار سكربت صغير (أو فحص يدوي) يطابق المفاتيح مع `GET /api/lookups` لكشف أي كتالوج ناقص.
- **القبول:** `npm run build` ينجح.

### المرحلة 1 — طبقة القراءة
- `lookupApi.catalogs()` و`useLookupCatalogs()` و`lookupKeys.catalogs`.
- **القبول:** الاستعلام يعيد المفاتيح ويُطابق البيانات الوصفية.

### المرحلة 2 — الكتابة (`features/lookup-manage`)
- Zod: `id` عدد صحيح موجب، `desc` و`descAr` غير فارغتين (بعد التقليم) وحتى 150 حرفًا.
- أربع mutations تُبطل `lookupKeys.all`.
- `LookupEntryFormDialog` بوضعين (إضافة/تعديل)، تعيين أخطاء الخادم إلى الحقول (`Lookup.IdAlreadyExists` على حقل المعرّف).
- **القبول:** أخطاء `400/404/409` تظهر بالعربية، لا رسالة إنجليزية.

### المرحلة 3 — الودجتان والصفحة
- `LookupCatalogPicker`: مجمّع حسب الوحدة، بحث، عدّاد قيم كل كتالوج لا يُحسب مسبقًا (يُحمَّل عند الاختيار فقط).
- `LookupEntriesTable`: أعمدة المعرّف (`dir="ltr"`)، التسمية العربية، الإنجليزية (`dir="ltr"`)، الحالة، تاريخ الإنشاء (مخفي افتراضيًا)؛ مرشح الحالة (الكل/نشط/موقوف) في الرابط؛ قائمة سياق للصف (تعديل، إيقاف/تفعيل، نسخ المعرّف) وللرأس والحالة الفارغة (إضافة، تحديث)، وكلها مفلترة بالصلاحية وقابلة للوصول بلوحة المفاتيح.
- حالات التحميل والخطأ مع إعادة المحاولة، وحالة «اختر كتالوجًا» عند غياب `?catalog=`، و`404` لكتالوج غير معروف في الرابط.
- **القبول:** سطر الصفحة ≤ 120، لا استيراد بين الشرائح الشقيقة إلا عبر barrel.

### المرحلة 4 — التكامل
- المسار والحارس وعنصر القائمة، وكتالوج الأخطاء (لا جديد غالبًا، يُراجَع فقط).
- أدلة `guides/lookups.ts` (`lookups.catalog`, `lookups.add`, `lookups.table`, `lookups.deactivate`…) وتشغيل `npm run lint`.

### المرحلة 5 — الوثائق
- README لكل مجلد جديد/معدّل (`features/lookup-manage`، `widgets/lookup-admin`، `pages/lookups`، `entities/lookup`، `shared/config`، `app/router`، `widgets/app-shell`) مع سجل التغييرات.
- `knowledge.md` (قسم Lookups + تصحيح العدد وسياسة القراءة)، والـ README الجذر، وCLAUDE.md إن لزم.

### المرحلة 6 — التحقق على API حي
- `admin`: عرض كتالوج، إضافة قيمة، تعديلها، إيقافها ثم تفعيلها، ومحاولة إيقاف قيمة مستخدمة (يجب `409` بالعربية)، وإضافة معرّف مكرّر، وكتالوج للقراءة فقط.
- مستخدم `user` بلا `LOOKUP_MANAGE`: لا عنصر في القائمة، والمسار المباشر يعيد صفحة عدم الصلاحية.
- التأكد من ظهور قيمة جديدة في قائمة منسدلة بشاشة أخرى (مثل نوع وثيقة) دون إعادة تحميل.
- الوضع الداكن، والجوال، وRTL، والتنقل بلوحة المفاتيح، واستمرار تفضيلات الأعمدة (`diwan.table.lookup-entries.columns.v1`).

## 6. المخاطر والملاحظات

| الخطر | المعالجة |
| --- | --- |
| إيقاف قيمة تعتمد عليها الواجهة بمعرّف ثابت (حالات الوثيقة، اتجاهاتها…) | شارة «نظامية» + تحذير في حوار التأكيد؛ الخادم يحمي المستخدَم فعلًا بـ `EntryInUse` لكن القيم غير المستخدمة بعد قد تُوقف |
| `staleTime: Infinity` يُبقي القوائم قديمة في تبويبات أخرى | الإبطال يخص التبويب الحالي؛ التبويبات الأخرى تتحدّث عند إعادة التحميل — مقبول ويُوثَّق |
| تعارض إضافة معرّف من مديرَين | يعالجه `409 IdAlreadyExists`؛ الحوار يبقى مفتوحًا ويقترح المعرّف التالي |
| كتالوج جديد في الخلفية لا يوجد في البيانات الوصفية | يظهر باسمه الإنجليزي ضمن «أخرى» وبـ `canCreate=true` افتراضيًا |
| عدم تدقيق (Audit) تغييرات المراجع | يُتحقَّق في المرحلة ب هل تُسجَّل؛ إن لم تكن فهي نقطة مفتوحة وليست من هذه الخطة |
| القراءة العامة بلا سياسة صلاحية واضحة | تصحيح التوثيق بعد الفحص |

## 7. نقاط مفتوحة تحتاج قرارًا

1. **المرحلة ب الاختيارية (خلفية):** نقطة تعيد عدد الاستخدامات لكل قيمة (`usageCount`) لإظهار عمود «مستخدمة في» ومنع محاولة إيقاف خاسرة مسبقًا. بدونها تعتمد الواجهة على رد `409`. التوصية: **تأجيلها**، والبدء بدونها.
2. هل يُسمح بتعديل المعرّف؟ التوصية: لا (غير مدعوم في الخلفية أصلًا).
3. هل تُعرض الكتالوجات «التقنية» (`notification-channels`, `notification-outbox-statuses`, `document-number-*`) للمدير؟ التوصية: تُعرض ضمن مجموعة مطوية «تقنية» مع تحذير.
4. هل المطلوب حذف نهائي؟ **لا** — الخلفية تدعم الإيقاف الناعم فقط.

## 8. خارج النطاق

- حذف القيم نهائيًا، أو تغيير المعرّف.
- إضافة قيم إلى `file-storage-providers` و`notification-types` (تُدار من وحداتها).
- استيراد/تصدير CSV للقيم.
- ترجمات لغات أخرى غير العربية والإنجليزية.
- شاشة إدارة «مخططات الحقول» (منفّذة مسبقًا في `pages/document-schemas`).

## 9. التقدير

مرحلة 0–1: صغيرة. مرحلة 2–3: العمل الأكبر (حوار + جدول). مرحلة 4–6: تكامل وتحقق. لا تغيير في الخلفية ولا في عدد الصلاحيات (تبقى 17).
